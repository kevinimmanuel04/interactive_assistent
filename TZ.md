# Техническое задание: Проект "Komorebi" (название условное)
**Цель:** Создание кроссплатформенного (Windows/macOS) виртуального ассистента с анимированным аниме-аватаром, работающего в гибридном режиме (Local + Cloud AI).

---

## 1. Общие требования
* **Производительность:** Потребление ОЗУ в режиме ожидания не более 200 МБ.
* **Автономность:** Базовый функционал должен работать без интернета.
* **Простота установки:** Один исполняемый файл или инсталлятор, скачивающий зависимости автоматически.
* **Приватность:** Все локальные запросы не покидают устройство пользователя.

---

## 2. Технологический стек
* **Ядро:** Go (Wails) или Rust (Tauri).
* **Интерфейс:** Vite + React/Vue (прозрачное окно WebView).
* **Визуализация:** Live2D (через Cubism SDK / PixiJS) или VRM (через Three.js).
* **Локальный AI:** Llama.cpp (бинарник) + модели GGUF (Llama 3.2 1B/3B, Phi-3.5).
* **Облачный AI:** OpenRouter API (Claude 3.5 Sonnet, GPT-4o).
* **Голос (STT):** Faster-Whisper или Whisper.cpp.
* **Голос (TTS):** Sherpa-ONNX или Piper (локально).

---

## 3. Функциональные возможности

### 3.1. Система визуализации (Аватар)
* **Overlay-режим:** Аватар отображается поверх всех окон с прозрачным фоном.
* **Система состояний (Animations):**
    * *Idle:* Дыхание, моргание, случайные движения.
    * *Listening:* Наклон головы, индикация ожидания.
    * *Thinking:* Анимация раздумья (например, прикладывание пальца к подбородку).
    * *Speaking:* Синхронизация губ (Lip-Sync) с аудиопотоком.
    * *Emotions:* Изменение выражения лица в зависимости от тона ответа нейросети (Joy, Sadness, Surprise).
* **Interaction:** Реакция на наведение мыши или клики (Drag-and-drop для перемещения по экрану).

### 3.2. Гибридный интеллект (Router Logic)
Система должна автоматически определять, куда направить запрос:
* **Локальная модель:** Приветствия, управление системой (громкость, яркость), простые вопросы, запуск приложений, погода.
* **OpenRouter:** Написание кода, сложный анализ текстов, перевод больших документов, философские беседы.
* **Ручной режим:** Возможность принудительного переключения через UI.

### 3.3. Голосовое взаимодействие
* **Wake Word Detection:** Активация по кодовому слову (например, "Hey, Yuki").
* **VAD (Voice Activity Detection):** Определение конца фразы для мгновенной отправки в STT.
* **Interruptible TTS:** Возможность перебить ассистента — если пользователь начинает говорить, ассистент замолкает.

### 3.4. Интеграция с ОС (Skills)
* **Контроль приложений:** Запуск/закрытие программ.
* **Системные команды:** Изменение громкости, создание скриншотов, управление плеером.
* **Буфер обмена:** Ассистент может анализировать скопированный текст (например, «Объясни, что в буфере»).
* **RAG (Local Memory):** Индексация локальных папок или файлов (PDF, TXT) для ответов по их содержимому.

## 5. Детальные требования к интерфейсу (UI)
* **Виджет настроек:** Скрытое меню (вызывается правой кнопкой по аватару).
* **Chat Bubble:** Текстовое облако над головой персонажа, которое плавно появляется и исчезает.
* **Input Field:** Минималистичная строка ввода (вызывается по Hotkey, например `Alt + Space`).
* **Статус-бар:** Маленький индикатор в углу, показывающий загрузку локальной модели или статус API.

## 6. Этапы разработки (Roadmap)

### Этап 1: Прототип (MVP)
* Создание прозрачного окна на Tauri/Wails.
* Отображение статичной аниме-картинки.
* Интеграция Llama.cpp и базовый текстовый чат.

### Этап 2: "Оживление"
* Подключение Live2D/VRM и базовых анимаций.
* Реализация STT (Whisper) и TTS (Piper).
* Настройка Lip-Sync.

### Этап 3: Интеллект
* Создание логики роутера (Local vs OpenRouter).
* Добавление системных команд (Skills).
* Оптимизация потребления ресурсов.

### Этап 4: Дистрибуция
* Написание скрипта для сборки всех бинарников в один инсталлер.
* Реализация системы авто-скачивания весов моделей при первом запуске.

---

## 7. Риски и решения
* **Риск:** Высокая нагрузка на GPU при рендеринге 3D.
    * *Решение:* Использование Live2D вместо VRM или ограничение FPS анимации в простое.
* **Риск:** Конфликты портов при использовании локальных серверов (Ollama и т.д.).
    * *Решение:* Использование динамических портов или прямой линковки библиотек через C-Bindings.
